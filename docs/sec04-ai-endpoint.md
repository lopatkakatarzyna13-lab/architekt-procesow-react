### Development branch: authenticated browser path

The workshop panel can use the Supabase Edge endpoint when both `VITE_WORKSHOP_AI_ENABLED=true` and `VITE_WORKSHOP_AI_MODE=supabase` are set at build time, with the existing Supabase URL and publishable key configured. The remote mode is disabled by default. The existing local development server path remains available in development. A dedicated Supabase client keeps AI authentication in memory, refreshes the session while the page is open, and requires a fresh login after reload. The browser sends the session access token to `workshop-ai`; the Edge function checks the owner independently. The CORS allowlist includes the Supabase SDK's `x-client-info` header while remaining restricted to the configured origin.

The isolated CI test exercises the application UI, local Supabase Auth, the Edge handler, PostgreSQL quota, the real adapter, and a provider response intercepted in a disposable test bootstrap. It also tests explicit review and AS-IS save/reopen. This does not establish production readiness or permission to deploy SQL or process confidential customer data. Earlier intermittent concurrent errors and socket closures remain unresolved even if later runs pass; the quota limits daily attempts, not concurrency or provider spending.

### Experimental database admission design (review only)

`experiments/supabase-auth/ai-concurrency-review.sql` is a separate, unapplied design. A locked singleton row combines a UTC-day attempt counter and one active lease; acquisition, quota increment and lease allocation occur in one PostgreSQL transaction. Only `service_role` may execute its functions. The release function requires the matching random lease ID, so a delayed release cannot clear a newer lease. A five-minute expiry permits recovery after a crashed worker; it is not a mathematically strict cap if an earlier provider request continues beyond the lease, or if the system clock changes. Release failure denies subsequent attempts until expiry. Never retry a request automatically after an ambiguous admission or provider timeout: it may have been counted or billed already.

This remains an experiment, not a migration. The development endpoint now uses the experimental acquire and release RPCs, fails closed when either storage call fails, and reports BUSY while another lease is active. It requires a reviewed migration, tests of worker termination and ambiguous release, repeated real Edge tests, and operational monitoring before it could be considered for deployment. A daily attempt limit and an expiring lease do not enforce a monetary spending cap. Provider-side billing controls must be independently verified for the actual account before enabling paid calls; do not assume that a usage alert stops spending.
